# M1: Foundation and synthetic data. Requirements

- **Status:** Draft, awaiting approval at the M1 Requirements gate
- **PRD links:** US-01 · FR-15 · NFR-02, NFR-05, NFR-06, NFR-07, NFR-08
- **Target release:** v0.2.0

## Goal

A developer can clone the repo, start the local stack with one command, and
generate a realistic, labeled set of purchase orders, receiving reports, and
invoices with **known** mistakes planted in them. This milestone produces the
demo data and the answer key that every later milestone is measured against.

## User stories in scope

| ID | Story |
|---|---|
| US-01 | As a developer, I want to generate realistic PO/RR/INV document sets with known errors and ground truth, so that I have demo data and an eval golden set. |

## Acceptance criteria

### A. Repo and tooling

- [ ] **AC-1 Clean setup.** On a clean macOS or Linux machine with Node LTS,
  pnpm, and Docker, the README's steps succeed with no manual fixes:
  `pnpm install` → `docker compose up -d` → `pnpm db:migrate` → `pnpm db:seed`.
- [ ] **AC-2 Workspace.** A pnpm workspace containing only the packages this
  milestone needs: `packages/core`, `packages/db`, `packages/generator`, and
  `evals/`. Other apps are added in their own milestones (see Q2).
- [ ] **AC-3 Quality commands.** `pnpm lint`, `pnpm typecheck`, and `pnpm test`
  all pass. TypeScript runs in strict mode. ESLint blocks `packages/core`
  from importing Prisma, Fastify, Next, or BullMQ (ADR-0001).
- [ ] **AC-4 CI.** A GitHub Actions workflow runs lint, typecheck, test, and
  the docs check (B-10) on every PR and push to `main`.
- [ ] **AC-5 Env.** Every env var is listed in `.env.example` and validated at
  startup. A missing or invalid var fails fast with a clear message.

### B. Database

- [ ] **AC-6 Schema.** The Prisma schema contains every entity in
  `architecture.md` §5. Money columns are `Decimal(14,4)` (ADR-0004). The
  initial migration applies cleanly to an empty database.
- [ ] **AC-7 Audit log is append-only.** A test proves that UPDATE and DELETE
  on `AuditEvent` raise an error, and that INSERT works (ADR-0005).
- [ ] **AC-8 Seed.** `pnpm db:seed` creates one user plus the vendors and
  catalog from the generator's catalog, so the DB and the documents agree. It
  is safe to run twice (no duplicates).

### C. Synthetic generator

- [ ] **AC-9 Command.** `pnpm generate --seed <n> --sets <n> --out <dir>`
  writes one folder per document set containing a PO, an RR, one or more
  invoices, and `ground_truth.json`. Files may be missing only where a
  "missing document" error was planted.
- [ ] **AC-10 Catalog.** About 200 SKUs across about 15 vendors, with realistic
  CPG product names, pack sizes, and prices. The same seed gives the same catalog.
- [ ] **AC-11 Variety.** At least 5 visually distinct vendor layouts. Across
  vendors they vary font, column order, header wording (e.g. "Qty" / "Units" /
  "Quantity Shipped"), date format, and SKU format. A set can have 1–25 line items.
- [ ] **AC-12 Planted errors.** Each error type has a configurable rate
  (CLI flag or config file):
  - short-ship (both kinds: billed for the full qty, and billed correctly, which is informational)
  - over-ship
  - billed but not received
  - price change on the invoice
  - description typos and abbreviations
  - SKU omitted on the invoice
  - missing document (PO, RR, or invoice)
  - duplicate invoice

  After each run, the command prints a summary table of how many of each type were planted.
- [ ] **AC-13 Answer key.** `ground_truth.json` validates against a Zod schema
  exported from `packages/core`. It contains:
  - the correct value of every field on every document
  - each field's page and bounding box
  - which lines match across PO, RR, and invoice
  - the expected exceptions: type, lines involved, dollar impact, and the
    informational flag

  Dollar impacts follow PRD FR-09 exactly.
- [ ] **AC-14 Arithmetic is correct.** On every document, qty × unit price =
  line total, the lines sum to the subtotal, and subtotal + tax + shipping =
  total. A test checks all 100 sets. Planted errors change values *between*
  documents, never the math *within* one.
- [ ] **AC-15 Scans.** A configurable share of documents (default 20%) is
  output as PNG "scans" with slight rotation, blur, and noise instead of PDF.
- [ ] **AC-16 Deterministic.** The same seed and config produce byte-identical
  files (same sha256), checked by a test that generates twice and compares (ADR-0006).
- [ ] **AC-17 Golden set.** `evals/golden-ci/` holds a fixed 20-set CI subset
  (PDFs, PNGs, and answer keys), committed with its set IDs listed in
  `evals/ci-subset.json`. The full ~100 sets are regenerated by command, not committed (PRD A3).
- [ ] **AC-18 Speed.** Generating 100 sets takes under 2 minutes on a laptop.

### D. Docs

- [ ] **AC-19** The README covers setup, the generate command and its options,
  and a sample of what a document set looks like (a screenshot and a short
  answer-key excerpt).

## Out of scope (later milestones or backlog)

- Reading documents with the LLM (M3), matching (M2), the eval harness and
  metrics (M2), API, UI, and worker (M4–M5)
- Retailer deductions (B-01), multiple receiving reports per PO (B-02), UOM conversion (B-03)
- Arithmetic errors *inside* a document (e.g. a wrong line total). This could
  be a future error type.

## Assumptions

- The answer key is computed **from the planted errors**, never by running a
  matching engine. Otherwise we'd be grading the matcher against itself.
- Fonts are open-licensed (OFL) and bundled in the repo, with no network
  needed at build time.
- Tax and shipping are simple: a flat rate and a flat fee per vendor.
